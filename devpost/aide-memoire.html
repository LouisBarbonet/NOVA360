Nouvel événement : règles de relecture

  • Distinguer statut du problème, décision antérieure et nouvelle proposition.
  • Aucune approbation inventée. « Livré » n'est pas « validé », « proposé » n'est pas « décidé ».
  • Ne fermer aucune autre condition sans preuve : elle va dans « ce qui ne change pas ».
  • Chaque changement est sourcé (nouvelle source + corpus). Vérifier les calculs de dates.
  • Le baseline reste intact. Ensuite : npm run worker:deploy, puis commit + push (site à jour en ≈ 1 min).
  • Fichiers : glisser-déposer (eml, pdf, xlsx, png…). Captures transcrites automatiquement : relire contre l'image.
  • Si l'analyse LLM échoue : remplir le JSON à la main dans le formulaire (il est éditable).
